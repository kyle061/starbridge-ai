# AiLink 支付与能力调研

调研对象：`https://ai.ailink1.com/keys`

## 公开可确认的能力

`/keys` 会跳转到登录页，未使用账号密码进入受保护页面。根据公开首页和服务条款，AiLink 对外强调：

- API Key 一键接入、密钥安全设置和使用管理。
- 按模型、接口、上下文长度、输入输出类型、工具调用及多模态请求计费。
- 额度、用量、账单、日志和用量分析。
- 速率限制、风险控制、批量/异步任务以及故障切换或排队能力。
- 失败重试、超时、流中断后，上游已经处理的请求仍可能产生费用；服务方建议调用方使用幂等键、预算、限流和告警。
- 服务方可以根据上游状态进行限流、排队、降级、故障切换或暂时停用能力。

公开条款没有披露具体支付渠道、费率、充值优惠或退款规则，因此这些内容不能据公开页面推断。进入登录后的支付页面需要真实账号授权，本次没有绕过登录或代填凭据。

## Starbridge 对照

Starbridge 已经具备：支付宝、微信、Stripe、Airwallex、EasyPay、多实例支付渠道、订单和 Webhook、余额充值、订阅、退款、支付审计、支付渠道限额、用量记录、批量图片任务、API Key 管理、低余额通知和管理员支付概览。因此没有重复实现一套支付渠道。

本次补齐的高价值缺口：

1. 用户支付下单支持 `Idempotency-Key`。网络超时或客户端重试时，服务端会重放原支付响应，避免重复创建支付订单；没有携带幂等键的旧客户端仍保持兼容。
2. 用户订单支持状态、订单类型、支付方式筛选，并支持按当前筛选条件导出 CSV 账单。

## 后续建议

如果要继续向企业版靠拢，优先级建议为：

1. 增加用户/团队级日预算、月预算和预算告警，并在请求前做原子额度检查。
2. 增加账单明细字段：模型、接口、缓存命中、工具调用、多模态类型、客户计费额和上游实际成本，并分别控制管理员和客户可见范围。
3. 增加支付渠道健康状态、自动故障切换结果和订单对账任务的用户可见状态。
4. 增加企业成员、角色、API Key 生命周期和按成员/Key 的消费归属。
