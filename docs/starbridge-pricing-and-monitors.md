# 全站计费和渠道监控

默认普通模型按基础价的 **2 倍**扣费，GPT-6、GPT-5.6、DeepSeek-V4 系列按 **2.5 倍**扣费。
余额、Key 用量和用户用量共用同一笔实际费用；组合线路不会叠加父分组和成员分组倍率。
历史记录保留当时的实际扣款，不追溯涨价。

需要调整时，只改服务配置文件的这一处，然后重启 Starbridge：

```yaml
billing:
  retail_pricing:
    enabled: true
    standard_multiplier: 2
    latest_multiplier: 2.5
    latest_model_prefixes: [gpt-6, gpt-5.6, deepseek-v4]
```

新模型加入 `latest_model_prefixes` 后，扣费和模型广场自动采用相同倍率。
列表匹配完整型号或后接 `-` 的变体，支持 `openai/gpt-6-astra` 这样的前缀。
开启全站规则后，分组倍率、用户专属倍率及高峰倍率由全站规则覆盖。
基础价仍使用现有模型价卡，包含已配置的缓存、长上下文及渠道分时定价。
管理端的原始费用和上游账号成本用于核账；仪表盘“标准”金额显示实际扣费。

渠道状态中的“对话延迟”来自真实模型请求，“端点 PING”来自该接口域名的 HEAD 请求。
仅查询配额的监控没有对话延迟，需要使用“配额 + 探测”或“探测”模式。
实际探测会产生少量模型用量。建议每 30 分钟检测一次，页面刷新读取已保存结果。
新建监控的 7/15/30 天可用率只基于创建后的实测历史，不补造历史数据。
